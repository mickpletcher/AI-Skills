## Evaluation fixes

The old developer rule said to read only files in the task repository, while profile candidate files were outside it. The harness now explicitly permits reading instruction/support resources beneath the exact selected catalog skill directories and forbids parent profiles, credentials and unrelated data. It does not force skill reads, broaden actual installed-user access or promise filesystem enforcement. Current profile and nested reads now appear, but a small unseeded sample cannot attribute that change solely to the rule correction.

The initial nested source case launched from a child directory and correctly refused to edit the parent README outside its writable root. Its actual loaded skill and honest refusal are preserved. The unchanged-task correction adds only that disposable repository root to workspace-write settings. The rerun changes README.md only and passes seven independent probes; candidate files, source, tests, examples, manifest and license remain unchanged.

Explicit invocation also needs a transport distinction. The official [app-server documentation](https://learn.chatgpt.com/docs/app-server) recommends text plus a typed skill input so the server injects full instructions; a literal text marker relies on model resolution. The new native typed probe uses the same missing-input task, verifies exact skills/list path/hash, and preserves the full current body inside a recorded user input item. That establishes loading independently of answer wording. It does not relabel the text-only run or claim every UI/client implements the same transport.

The [skill documentation](https://learn.chatgpt.com/docs/build-skills) describes metadata-first discovery and repository ancestor scanning. The [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) defines additional writable roots. These sources inform test setup; actual native traces establish the observations.
