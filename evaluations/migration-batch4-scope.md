Mick authorized the remaining-skill round after the Codex frontmatter and helper checks. It covers the 26 domain skills without prior behavioral captures, with one supplied-evidence task and one boundary/missing-input task each: 52 sessions plus a shell/file canary. Preparation and completed sessions are distinct; results and acceptance must be recorded separately.

The scope includes alpaca-trading, astrophotography-processing, blog-post, blog-to-social, container-home, crypto-listings, crypto-research, facebook-post, facebook-reply, fitness-log, fitness-programming, food-analyzer, idea-forge, linkedin-post, market-brief, obsidian-workout-export, patentforge-provisional, pihole-blocklist, proxmox-lxc, resume-writer, travel-itinerary, travel-planning, travel-research, website-content, x-post and x-reply.

The three allowed Codex candidates use their generated Codex entrypoints. The other 23 use their existing generated ChatGPT instructions through the CLI as explicitly labeled behavioral proxies. This does not add Codex placement or certify native ChatGPT/Claude.

Each case receives only its selected candidate, relevant supporting files, synthetic prompt and workspace. Separate assessment criteria and previous conclusions stay outside the session inputs. Capture exact candidate/resource/fixture hashes, CLI/model/settings, initial context audit, raw response/tool trace and file effects. Use the existing model setting, `gpt-6.1-sol` with medium reasoning, one forced-instruction run per case. This does not evaluate routing, control comparisons or variability.

Network, apps, plugins, unrelated skills, memory and delegation are disabled. No live infrastructure, broker calls, market lookups, medical/legal decisions, purchases, bookings, publication, real notes or scheduler changes. Missing current evidence must remain unverified. Only synthetic task material may be sent to inference; credentials and raw traces stay outside the checkout and sync roots. Preserve the source login, remove the temporary evaluation copy in `finally`, and record cleanup evidence.

Before domain sessions, require a real canary plus exact supplied developer/user input matching and an unrelated-context exclusion audit. Stop on context/runtime capture failure rather than treating it as a skill pass. Assess actual outputs and tool effects against the separately authored criteria. Retain all failures and report bounded assistant assessment separately from human acceptance. Keep PR #11 draft; no installation, merging or promotion.
