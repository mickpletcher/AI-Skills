# Design

The master entrypoint routes between schema-driven fixtures and target-skill analysis. Focused references cover the bounded helper format, target analysis/provenance, and custom output/oracle semantics. Capability and ecosystem declarations keep all four generated placements proposed.

A standard-library helper implements a small explicit field contract, deterministic SHA-256-derived fictional values, valid baselines and isolated checked mutations. Output is JSON or CSV with a typed missing/null sidecar. Intentional malformed JSON stays a separate raw fixture. Limits, no-overwrite behavior, unsafe spreadsheet text refusal, and unknown-contract rejection are explicit.

A separate scenario materializer copies a reviewed fictional recipe only after reading and matching each pinned source hash. It validates output names and preserves fixed recipe inputs, traceability, numeric/qualitative expectations and not-run state. It never invokes the target skill or visits fixture endpoints. Hash equality establishes inspected source identity, not complete behavioral alignment or current official API semantics.

The Pi-hole pilot records 13 traced requirements and 12 cases; numeric oracle tests use independent CSV parsing and counts. Synthetic helper regressions and an independent forward review supplement structural validation. Native host/model routing and qualitative Pi-hole behavior remain untested.
